# Language / locale

## CDE — English only (нет русского в CDE 2.5.3)

CDE (Common Desktop Environment) **2.5.3 не содержит русской локализации**.

Проверено по исходникам (`programs/localized/`): доступны только каталоги
сообщений:

```
C (английский, дефолт)
de_DE.UTF-8  fr_FR.UTF-8  es_ES.UTF-8  it_IT.UTF-8  sv_SE.UTF-8
el_GR.UTF-8  ja_JP.UTF-8  ko_KR.UTF-8  zh_CN.UTF-8  zh_TW.UTF-8
```

`ru_RU.UTF-8` **отсутствует** (вверх по течению CDE так и не переведён на
русский). Поэтому рабочий стол CDE (dtwm/dtterm/dtfile/dtpad, меню, диалоги)
остаётся англоязычным — это ограничение самого CDE 2.5.3, а не сборки.

## System locale — C.UTF-8 по умолчанию

`/etc/profile` задаёт `LANG=C.UTF-8` и `LC_ALL=C.UTF-8` (встроенная в glibc
локаль — не требует генерации через `localedef`). Это нужно для `btop` (он
требует UTF-8 в окружении), `fastfetch` и корректного отображения UTF-8 в
терминале.

## Как включить русский в консоли (опционально)

Сам CDE останется англоязычным, но **системную локаль можно переключить на
русскую** для консольных утилит (`ls`, `date`, сообщения `btop`, `fastfetch`):

```sh
# 1. сгенерировать русскую glibc-локаль (нужен localedef):
#    (в образе его нет; собрать host-localedef, либо на собрать образ с
#     BR2_GENERATE_LOCALE="en_US.UTF-8 ru_RU.UTF-8" — но в текущем Buildroot
#     2026.05 этот список применяется только к uClibc-ng, для glibc локаль
#     генерируется отдельно через localedef)
localedef -i ru_RU -f UTF-8 ru_RU.UTF-8

# 2. переключить (на лету или в /etc/profile):
export LANG=ru_RU.UTF-8
export LC_ALL=ru_RU.UTF-8
```

Замечание: базовый образ по умолчанию **C.UTF-8** (английский) — чтобы не тянуть
лишнюю генерацию локалей на 64 MB-машине. Русская консоль доступна при желании
по шагам выше; русский в CDE невозможен по причине отсутствия перевода в CDE 2.5.3.
